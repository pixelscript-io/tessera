# The Tessera landing page

The page at tessera.pixelscript.io, built with Tessera itself: a Tessera app with its own design tokens (`system/tokens`), its own components (`app/components`), one page and one layout. It is the first real application built with the framework, and what it needed that the framework lacked was added to the framework (SVG in templates, `ref`, the `tabs` behavior).

```bash
pnpm --filter tessera-landing dev        # http://localhost:5173
pnpm --filter tessera-landing check      # the compiler's checks: tokens, contrast, contracts
pnpm --filter tessera-landing build      # tessera build --prerender, into dist/
```

## How it is put together

- `system/tokens`: the page's tokens, on a 2px grid. Every space, font size and radius is a multiple of 2px, and the steps are named by their pixels (`$space.12` is 12px). `system/components` is empty on purpose: it stops Tessera from using the repository's own design system in its place.
- `app/components`: one component for each part of the page, each with a contract. Styles use tokens only; the two `raw()` uses are the fluid headline sizes, with a reason and an expiry.
- `app/data`: the words and code samples the components show.
- `app/version.ts`: generated by `scripts/version.mjs` from `packages/tessera/package.json` before `dev` and `build`, so the page always names the published version. A test checks it.
- `app/**/*.browser.test.ts`: the accessibility suite generated from the contracts, and tests for every interaction and an axe scan of the whole page. They run with the rest of the tests: `pnpm test`.

## Deploying

Every push to `main` builds the page and deploys it to a Cloudflare Worker (`wrangler.jsonc`, worker `tessera-landing`) with `.github/workflows/landing.yml`. The address tessera.pixelscript.io is added to the worker in the Cloudflare dashboard (Settings, Domains & Routes).
